Giai đoạn 1: Tối ưu macOS System & UX nền tảng

Xoá bỏ độ trễ bàn phím, kích hoạt góc nhìn chuẩn lập trình trong Finder và cử chỉ Trackpad nhanh.

Hệ thống

1.1. Tăng tốc độ bàn phím & Tắt menu giữ phím Apple

Bắt buộc cho dân code/Vim/Cursor: Giảm thời gian chờ trước khi lặp phím và tăng tốc độ lặp lại lên mức tối đa. 

# Set ultrafast key repeat rate and low initial delay
defaults write -g InitialKeyRepeat -int 15
defaults write -g KeyRepeat -int 2

# Disable press-and-hold popup in favor of real key repeating
defaults write -g ApplePressAndHoldEnabled -bool false

# Disable automatic period substitution on double-space
defaults write -g NSAutomaticPeriodSubstitutionEnabled -bool false

1.2. Cử chỉ Trackpad & Chạm để nhấp (Tap to Click)

Bật chạm nhẹ để click không cần nhấn lún, tăng tốc độ rê chuột và cử chỉ chuyển desktop. 

# Enable Tap-to-click on built-in and Bluetooth Trackpads
defaults write com.apple.driver.AppleBluetoothMultitouch.trackpad Clicking -bool true
defaults write com.apple.AppleMultitouchTrackpad Clicking -bool true
defaults -currentHost write NSGlobalDomain com.apple.mouse.tapBehavior -int 1
defaults write NSGlobalDomain com.apple.mouse.tapBehavior -int 1

# Increase mouse/trackpad speed
defaults write NSGlobalDomain com.apple.trackpad.scaling -float 3.0

1.3. Tối ưu Finder chuẩn Lập trình viên

Luôn hiện đuôi file, thanh đường dẫn, thanh trạng thái, gom folder lên đầu và chặn rác file .DS_Store. 

# Always show all file extensions
defaults write NSGlobalDomain AppleShowAllExtensions -bool true

# Show Path bar and Status bar
defaults write com.apple.finder ShowPathbar -bool true
defaults write com.apple.finder ShowStatusBar -bool true

# Keep folders on top when sorting by name
defaults write com.apple.finder _FXSortFoldersFirst -bool true

# Prevent .DS_Store file creation on USB and Network volumes
defaults write com.apple.desktopservices DSDontWriteNetworkStores -bool true
defaults write com.apple.desktopservices DSDontWriteUSBStores -bool true

# Apply changes by restarting Finder
killall Finder

Tính năng Pro: Trích xuất & Khôi phục Setting máy Mac hiện tại

Tự động hóa

Bạn muốn lưu lại toàn bộ các thiết lập cử chỉ Trackpad, tốc độ bàn phím, cấu hình Finder và Dock hiện tại của máy bạn thành 1 file script để sau này dùng cho máy mới? Hãy dùng công cụ xuất tự động dưới đây.

1 Bước 1: Trích xuất Setting

Chạy script để tự động đọc các thiết lập bạn đang dùng trên máy này.

2 Bước 2: Lưu vào `backups/`

File khôi phục được sinh ra gọn gàng trong thư mục `backups/` để bạn lưu trữ.

3 Bước 3: Khôi phục 1-Click

Khi sang máy Mac mới, chỉ cần chạy file backup là mọi thiết lập tự động áp dụng 100%.

File script trong dự án: scripts/export-macos-settings.vi.sh

Chạy lệnh này trên máy Mac hiện tại để trích xuất setting: 

bash scripts/export-macos-settings.vi.sh

File khôi phục được tạo tại: backups/apply-my-settings.vi.sh

Khi cài máy Mac mới, chỉ cần copy file này sang và chạy: 

bash backups/apply-my-settings.vi.sh

Giai đoạn 2: Package Manager & Bộ CLI Hiện đại

Cài đặt Xcode CLI Tools, Homebrew, Starship prompt, và bộ công cụ dòng lệnh thế hệ mới viết bằng Rust/Go.

CLI & Công cụ

2.1. Xcode Command Line Tools & Homebrew

Nền tảng quản lý gói chuẩn cho macOS, tự động tối ưu đường dẫn cho chip Apple Silicon.

Apple Developer (Xcode CLT) Homebrew Official (brew.sh) 
# 1. Install Apple Command Line Tools (Clang, Make, Git)
xcode-select --install

# 2. Install Homebrew
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 3. Configure Homebrew PATH in ~/.zprofile for Apple Silicon
(echo; echo 'eval "$(/opt/homebrew/bin/brew shellenv)"') >> ~/.zprofile
eval "$(/opt/homebrew/bin/brew shellenv)"

2.2. Starship Prompt Siêu tốc & Đẹp mắt

Prompt viết bằng Rust cực nhẹ (<1ms), hiển thị nhánh Git, file thay đổi, phiên bản Node/Python và thời gian chạy lệnh.

Starship Official (starship.rs) 
# Install Starship via Homebrew
brew install starship

# Append Starship initialization to ~/.zshrc

2.3. Bộ công cụ CLI Thế hệ mới (Tuỳ chọn)

Tick chọn hoặc bỏ chọn các công cụ bạn muốn. Mỗi tool thay thế một lệnh Unix cũ với tốc độ nhanh gấp 10-50 lần.

Đã chọn 9/9 công cụ
eza Thay thế `ls`

Là gì: Trình duyệt danh sách file/thư mục viết bằng Rust, hiển thị icon, màu sắc phân quyền, xem cây thư mục lồng nhau (`--tree`).

Tại sao: Hiển thị ngay trạng thái Git của từng file (đã sửa, chưa track) và màu sắc trực quan, không bị đơn điệu như lệnh `ls` cũ.

bat Thay thế `cat`

Là gì: Trình đọc nội dung file trong terminal với tính năng tô màu cú pháp theo từng ngôn ngữ (JS, Python, Rust...).

Tại sao: Hiển thị số dòng rõ ràng, vạch chỉ báo thay đổi Git diff ở lề trái, đọc code nhanh không cần mở editor.

ripgrep (rg) Thay thế `grep`

Là gì: Công cụ tìm kiếm chuỗi / regex trong toàn bộ repo với tốc độ nhanh nhất thế giới.

Tại sao: Tự động bỏ qua các folder rác (node_modules, .git) theo .gitignore, tìm code trong repo triệu dòng chỉ mất vài mili-giây.

fzf Tìm kiếm mờ

Là gì: Bộ lọc tìm kiếm mờ (Fuzzy finder) đa năng cho file, lịch sử lệnh terminal, git branch.

Tại sao: Nhấn `Ctrl + R` để tìm lại bất kỳ câu lệnh nào từng gõ chỉ với vài ký tự không cần nhớ chính xác toàn bộ.

zoxide (z) Thay thế `cd`

Là gì: Công cụ điều hướng thông minh tự nhớ các thư mục bạn hay làm việc.

Tại sao: Chỉ cần gõ `z tên_dự_án` là nhảy ngay vào thư mục làm việc, tiết kiệm hàng trăm lần gõ đường dẫn dài mỗi ngày.

gh (GitHub CLI) GitHub CLI

Là gì: Công cụ dòng lệnh chính thức của GitHub giúp quản lý repo, Pull Request, Issue, CI/CD Actions.

Tại sao: Tạo PR (`gh pr create`), clone repo (`gh repo clone`) và đăng nhập GitHub một chạm không cần copy SSH key thủ công.

tldr Sổ tay lệnh

Là gì: Tra cứu hướng dẫn ngắn gọn cho mọi lệnh terminal kèm ví dụ thực tế dễ hiểu.

Tại sao: Thay vì đọc tài liệu dài hàng nghìn dòng của lệnh `man`, `tldr tar` chỉ cho bạn đúng 3 ví dụ thực chiến cần dùng.

jq Xử lý JSON

Là gì: Bộ xử lý, định dạng đẹp và trích xuất dữ liệu JSON từ API/terminal.

Tại sao: Định dạng kết quả `curl` JSON rõ ràng, trích xuất nhanh trường dữ liệu mà không cần viết script riêng.

yq Xử lý YAML

Là gì: Trình xử lý dữ liệu YAML, XML, CSV trực tiếp trên dòng lệnh.

Tại sao: Cực kỳ tiện lợi khi chỉnh sửa file Docker Compose, Kubernetes và GitHub Actions workflow tự động.

Lệnh cài đặt Homebrew tự động cập nhật: 
brew install eza bat ripgrep fzf zoxide gh tldr jq yq

2.4. Cấu hình Aliases & Tích hợp Shell (`.zshrc`)

Tự động kích hoạt các công cụ mới khi gõ các lệnh quen thuộc và nạp phím tắt cho Zoxide/FZF. 

# Append smart aliases and tool completions to ~/.zshrc
cat << 'EOF' >> ~/.zshrc

# --- Modern CLI Aliases ---
alias ls="eza --icons --group-directories-first"
alias ll="eza -la --icons --group-directories-first --git"
alias lt="eza --tree --level=2 --icons"
alias cat="bat --paging=never"
alias grep="rg"

# --- Zoxide (Smarter `cd`) & FZF Setup ---
eval "$(zoxide init zsh)"
source <(fzf --zsh)
EOF

# Apply changes to current terminal session
source ~/.zshrc

Runtime & Docker

3.1. `mise` — Trình Quản lý Đa Phiên bản Ngôn ngữ (Thay thế nvm, pyenv, rbenv)

Viết bằng Rust, nhanh gấp 20 lần nvm, không làm chậm terminal khi mở tab mới, tự động đổi version Node/Python/Go theo từng dự án.

mise Official (mise.jdx.dev) 
# Install mise via Homebrew
brew install mise

# Activate mise in ~/.zshrc
echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
source ~/.zshrc

# Install and set global Node.js LTS
mise use --global node@lts

3.2. Bộ công cụ JS/TS Siêu tốc: `bun` & `pnpm`

`bun` chạy script/test nhanh gấp 10-30 lần và cài gói tức thì; `pnpm` tối ưu dung lượng ổ cứng tối đa cho monorepo.

Bun Official (bun.sh) PNPM Official (pnpm.io) 
# Install Bun (Blazing-fast JS runtime, bundler & test runner)
curl -fsSL https://bun.sh/install | bash

# Install PNPM (Fast, disk space efficient package manager)
brew install pnpm

3.3. Bộ công cụ Python Hiện đại: `uv` (Thay thế pip, virtualenv, poetry)

Viết bằng Rust bởi đội ngũ Astral, `uv` nhanh gấp 10-100 lần pip, quản lý phiên bản Python, môi trường ảo và thư viện trong một công cụ duy nhất.

Astral uv (astral.sh/uv) 
# Install uv via Homebrew
brew install uv

# Quick Example: Create a Python virtualenv in 10ms
# uv venv
# uv pip install fastapi uvicorn

3.4. Chạy Docker & Linux VM Siêu nhẹ: `OrbStack`

Khởi động trong 2 giây, tốn ít hơn 80% RAM so với Docker Desktop, gần như 0% CPU khi idle, tương thích 100% với lệnh docker và docker-compose.

OrbStack Official (orbstack.dev) 
# Install OrbStack (Lightweight Docker & Linux VM engine)
brew install --cask orbstack

4.3.6. File Cấu Hình Chuẩn Mực `.cursorrules` / `RULE.md`

Đặt ở thư mục gốc dự án để ép AI tuân thủ chuẩn TypeScript strict, không sinh code thừa và viết commit chuẩn mực. 

# Create .cursorrules in project root
cat << 'EOF' > .cursorrules
# Engineering Standards & Load-Bearing Invariants

## 1. Core Philosophy
- Correctness first, then maintainability 6 months out.
- Apply taste: delete weightless code, refuse needless abstractions, prefer boring and robust designs.
- Zero code bloat: Never avoidably allocate, copy, or compute. Delete dead imports and obsolete helpers immediately.

## 2. Strict Type System & Architecture
- Strict TypeScript: Absolute prohibition of `any` or loose type assertions (`as unknown as T`). Explicit return types on all exported functions.
- Single source of truth: Schema validation (Zod) -> infer TypeScript types directly.

## 3. Surgical Edits & Git Integrity
- Never touch unrelated lines or format files arbitrarily outside the requested prompt scope.
- Before editing exported symbols, check all callsites to prevent silent regressions.
- Commit messages MUST adhere to Conventional Commits: `feat(scope): ...`, `fix(scope): ...`, `refactor(scope): ...`.

## 4. Verification & Testing Deliverable
- Never claim a task is "done" without concrete verification proof:
  - Run the specific test file or smoke test command covering the changed logic.
  - Report exact test output and edge cases covered.
EOF

4.3.7. Cẩm Nang Vibe Coding Chuyên Nghiệp & Làm Chủ `omp` Harness

Từ người mới gõ prompt mò mẫm trở thành AI Tech Lead: Làm chủ sức mạnh của persistent kernel, phân quyền subagent, sửa code chính xác và định tuyến đa model.

1. Chuyển Đổi Tư Duy: 'Prompt & Pray' vs. 'AI Tech Lead'
Vibe Coding Nghiệp Dư (❌ Tránh)
  • • Prompt sơ sài: "Viết app todo", "Sửa lỗi login giúp tôi".
  • • Quá tải ngữ cảnh: Bắt AI quét 500 file một lúc ➔ Tràn context, sinh ảo giác (hallucination).
  • • Ghi đè cả file: Để AI viết lại 300 dòng code chỉ để đổi 1 biến ➔ Mất code cũ.
  • • Tin lời AI mù quáng: Chấp nhận code khi AI bảo "Xong rồi" mà không đòi bằng chứng test.
AI Tech Lead Chuyên Nghiệp (✅ Chuẩn)
  • • Đưa ra Spec & Ràng buộc: Bạn là kiến trúc sư, xác định rõ Input/Output & Type.
  • • Định hướng tối thiểu: Chỉ định chính xác file `auth.ts:40-100` hoặc giao `scout` quét trước.
  • • Surgical Diff: Dùng `edit` / `ast_edit` chỉ thay đổi đúng 2-3 dòng cần sửa.
  • • Evidence-First: Chỉ nghiệm thu khi AI cung cấp lệnh chạy test pass và Git diff.
2. Công Thức Prompt 3 Thành Phần Cho Agent Chính Xác 99%
1. GOAL (Mục tiêu)

Cần làm gì, ở hàm/file cụ thể nào.

2. CONSTRAINTS (Ràng buộc)

Không dùng `any`, giữ nguyên type cũ, không sửa file ngoài scope.

3. ACCEPTANCE (Nghiệm thu)

Lệnh test cụ thể hoặc cURL mẫu để chứng minh hoạt động.

Ví Dụ Thực Tế Prompt Chuẩn Tech Lead:
"Thêm Rate Limiting (10 req/phút) vào file `src/routes/auth.ts:35-80`.
Ràng buộc: Dùng Redis token bucket; không thay đổi signature hàm `authenticate()`; TypeScript strict không `any`.
Nghiệm thu: Chạy `npm test tests/rate-limit.test.ts`, báo cáo kết quả và show git diff các dòng thay đổi."
3. Cách Điều Phối `omp` Harness & Các Công Cụ Lõi
Phân Phối Subagents Thông Minh

• Đọc hiểu/Nghiên cứu: Giao cho scout (chạy model rẻ vibe-fast) để quét pattern trước.
• Thực thi code: Giao cho task (model mạnh vibe-coder) sửa file.
• Kiểm tra an toàn: Giao cho security-reviewer quét rò rỉ token hoặc SQL injection.

Tận Dụng Persistent Kernel & AST

• `eval`: Chạy code JavaScript/Python trực tiếp trong RAM ảo, lưu trữ biến số qua nhiều turn mà không cần tạo file nháp.
• `xd://ast_edit`: Sửa code cấu trúc AST, tuyệt đối không làm rách cú pháp ngoặc nhọn hay lỗi thụt đầu dòng.
• `xd://lsp`: Rename hàm/biến xuyên suốt toàn bộ codebase với Language Server chuẩn xác 100%.

Kiến Trúc Vibe Coding: Multi-Agent, Review & E2E Testing

Cẩm nang kiến trúc chuyên sâu cho AI Tech Lead & Hệ thống Autonomous Agent

1. Khởi Tạo Dự Án: Specs, Plans, Rules, Skills & Hooks
Specs & Plans (`specs/` / `PLAN.md`)

• Bắt buộc cho mọi task từ 3 bước trở lên.
• Nội dung: Định nghĩa Goal (Mục tiêu), Interface/Contract (Kiểu dữ liệu TypeScript/Zod), và các Phase chia nhỏ để Agent làm đến đâu tick `[x]` đến đó.

Rules (`.cursorrules` / `RULE.md`)

• Luật bất biến: Nằm ở thư mục gốc dự án.
• Ép AI luôn tuân thủ: TypeScript strict không `any`, commit theo chuẩn `feat: ...`, tuyệt đối không format file ngoài phạm vi yêu cầu.

Skills (`.agents/skills/*/SKILL.md`)

• Công thức chuyên biệt: Hướng dẫn Agent cách thực hiện các tác vụ phức tạp (như `security-audit`, `database-migration`, `generate-canvas`).

Hooks (`.cursor/hooks.json`)

• Kích hoạt tự động: Chạy linter tự động trước khi save, chặn agent sửa `.env`, hoặc kích hoạt test suite khi file code thay đổi.

2. Phân Luồng Git Worktree & Giao Tiếp Đa Agent

Khi phát triển song song nhiều tính năng, tuyệt đối không để nhiều Agent chạy chung một thư mục. Thay vào đó, mỗi Agent được cấp một Git Worktree độc lập: 

MAIN AGENT (Tech Lead & Contract Owner)
   ├── Worktree 1: /tmp/wt-api (Branch: feat/api)  --> Agent A: Viết backend & database
   ├── Worktree 2: /tmp/wt-ui  (Branch: feat/ui)   --> Agent B: Viết React & Tailwind CSS
   └── Worktree 3: /tmp/wt-doc (Branch: docs/api)  --> Agent C: Viết OpenAPI & Specs
• Chốt Contract Trước (Shared Schema):

Main Agent định nghĩa sẵn file schema chung (`types/auth.ts`). Agent Frontend dựng UI theo contract đó, Agent Backend viết endpoint khớp 100% schema.

• Giao Tiếp Phi Phong Tỏa (Non-Blocking Hub):

Các Agent nhắn tin trao đổi qua Hub messaging phi tập trung, không chặn vòng lặp thực thi của nhau.

3. Quy Trình Code Review Tự Động Trước Khi Merge

Trước khi hợp nhất code từ Worktree vào nhánh chính `main`, subagent reviewer và security-reviewer sẽ kiểm tra độc lập theo 4 tiêu chuẩn:

1. Scope & Surgical Diff

Đảm bảo chỉ sửa đúng các dòng được yêu cầu, không tự ý sửa format hoặc xóa comment của dự án.

2. Type Safety & Invariants

Tuyệt đối không dùng `any`, không ép kiểu lỏng lẻo (`as unknown as T`), giữ nguyên Type cha.

3. Edge Case Coverage

Bắt buộc xử lý các trạng thái biên: `null`, `undefined`, `empty array`, lỗi mạng timeout.

4. Security Leak Defense

Quét lỗ hổng SQL Injection, Command Injection, hardcoded API key hoặc token rò rỉ.

4. Kiểm Thử Thực Chiến: Test API, Web UI & User Clicks
A. Test API Backend (REST / GraphQL)

Agent chạy trực tiếp test runner (`bun test`, `vitest`, `pytest`) hoặc bắn request cURL thật vào server ngầm:

curl -s -X POST http://localhost:3000/api/v1/auth/login \ -H "Content-Type: application/json" \ -d '{"email":"test@dev.io","password":"pass"}' | jq .

✅ Nghiệm thu: Status 200, JWT token hợp lệ, DB cập nhật đúng.

B. Test Web UI & User Click (Headless Browser)

Agent điều khiển Chromium headless qua thiết bị `xd://browser`:

  • 1. `open`: Mở URL dev `http://localhost:5173/checkout`.
  • 2. `observe`: Quét cây Accessibility Tree (ARIA refs).
  • 3. `fill` & `click`: Điền form và bấm nút thanh toán.
  • 4. `screen`: Chụp ảnh màn hình làm bằng chứng trực quan.

✅ Nghiệm thu: Form submit thành công + có ảnh chụp screenshot.
